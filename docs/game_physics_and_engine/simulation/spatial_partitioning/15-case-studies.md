# Case studies

Shipping engines rarely use one structure for everything; they pick per job.
Bullet Physics: DbvtBroadphase

Bullet's default broadphase is btDbvtBroadphase[21], a pair of dynamic AABB trees: one for proxies that have moved recently and one for proxies that have stayed still. The btDbvt class is a dynamic bounding volume tree with incremental insertion and removal. A new leaf descends toward whichever child box is closer by a cheap center-distance test, not an SAH cost, and an incremental optimization pass removes and re-inserts a few leaves each frame, following a different root-to-leaf path each time. Proxies migrate from the moving tree to the still one once they stop, and back when they move.
Unreal Engine: TOctree2

Unreal's generic octree, TOctree2, keeps its nodes in flat arrays (a node array, parent links, and a free list of recycled node slots) rather than as individually allocated nodes[25]. Elements are added and removed individually, so a moving object is removed and re-added rather than the tree being rebuilt. Physics overlap and trace queries do not go through it: they run against the physics engine's own acceleration structures. Nanite's cluster culling uses yet another structure, covered below.
PhysX (and Unity): broadphase versus scene queries

PhysX, which Unity integrates for 3D physics, does not use a BVH for its broadphase. Its documented broadphase types are sweep-and-prune (eSAP), multi box pruning (eMBP), automatic box pruning (eABP), a parallel variant (ePABP), and a GPU implementation[14]. PhysX's AABB tree is the scene-query pruner, serving raycasts and overlaps, which is a separate stage from pair-finding. Keeping those two apart matters: the broadphase answers "which pairs might touch this frame", the scene-query structure answers "what does this ray hit". Jolt, used on Horizon Forbidden West, takes a third route: its broadphase is a quadtree of AABBs (four children per node) whose nodes are expanded in place as bodies move, and a tight replacement tree is built in the background during the next physics step and swapped in before the step ends[15].
Nanite: cluster culling hierarchy

Nanite (Unreal Engine 5) groups triangles into clusters of 128 and simplifies them into a hierarchy that is a DAG rather than a tree, because the merge-and-split step leaves a simplified parent shared by the groups it came from[23]. Culling runs against a second structure built over the clusters: an eight-wide BVH whose leaves are the group-sized cluster lists and whose internal nodes carry the maximum of their children's ParentError. Keying on ParentError rather than the cluster's own error is the key design choice, and the talk gives the reason: any cluster whose parent error is already under the threshold can be culled, so "an acceleration structure for LOD culling should be based on ParentError, not the ClusterError itself." Both structures are built offline at asset import, not at runtime.
RTX TLAS/BLAS

The DirectX and Vulkan ray tracing APIs expose a two-level BVH. The BLAS contains per-mesh triangle geometry, built once (or refit or rebuilt for deformable meshes). The TLAS contains instance transforms and BLAS references, rebuilt or refit every frame. On NVIDIA hardware, RT Cores accelerate BVH traversal and ray-triangle intersection[19]. What the driver does inside the build cannot be observed through the API: both DXR and Vulkan describe the acceleration structure as opaque and specify no construction algorithm[17]. The application's levers are how geometry is split into BLASes and instances, the build-quality hints, update-versus-rebuild, and compaction. Read PREFER_FAST_TRACE as what the spec actually promises, a rule of thumb of "about 2-3 times the build time than default in order to get better tracing performance", rather than as an instruction to run a binned SAH build.
