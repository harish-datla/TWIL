# From text predictor to assistant

Pretraining teaches a model to continue text the way text usually continues. An assistant needs different behavior: answer the question, follow the instruction, prefer the helpful reply. That behavior is added afterwards, in stages that reuse the pretrained weights and the same next-token machinery but change the data and the loss. Meta's Llama 3 is one documented example. Its instruction-tuned models came from the pretrained ones through supervised fine-tuning (more training on example answers) followed by reinforcement learning from human feedback, using public instruction data plus over ten million human-annotated examples.[1]

These stages cost far less than pretraining. Stanford's Alpaca fine-tuned a 7-billion-parameter model on 52,000 example instructions and answers, which a stronger model generated for under $500 of API calls. Training ran for three epochs (passes over the data) at a learning rate of 2e-5 and batch size 128, on one machine with four 80 GB A100 GPUs.[2] The preference stages need a different kind of data: judgments of which of two outputs is better. OpenAI's summarization work collected tens of thousands of human comparisons between two summaries, and Anthropic's HH-RLHF dataset pairs a chosen and a rejected dialogue reply for helpfulness and harmlessness.[3][4]

Every widget on this page uses the same kind of small model built in Train a Language Model: one transformer block that predicts the next character. It's pretrained in your browser on sentences about a farm, then taught something else.
