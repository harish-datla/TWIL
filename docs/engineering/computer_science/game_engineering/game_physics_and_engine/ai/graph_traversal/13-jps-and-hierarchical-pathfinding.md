# JPS and hierarchical pathfinding

An RTS map 1,000 cells on a side has a million cells, and a few hundred units asking for paths every second. Plain A* expands more nodes as maps grow; two optimizations cut that count on large grid maps:

Jump Point Search (Harabor & Grastien, AAAI 2011[20]) exploits a symmetry property of uniform-cost 8-connected grids: many paths through open space are interchangeable. JPS prunes the search by skipping intermediate cells that no optimal path needs to expand, jumping directly to "jump points": cells next to an obstacle corner where an optimal path may turn, and the goal. The paper reports speedups over A* from about 2× on short paths to about 30× on long ones, on HOG2 maps from Baldur's Gate II and Dragon Age: Origins plus two synthetic sets. JPS is restricted to uniform-cost grids (variable terrain cost breaks its symmetry argument), but for tile-based maps where every cell is either walkable or blocked it is a common choice.

Hierarchical Pathfinding A* (HPA*, Botea, Müller, Schaeffer, 2004[19]) partitions the map into clusters at one or more abstraction levels. At build time, it places entrance nodes on the borders between neighboring clusters and, inside each cluster, computes the shortest path between every pair of that cluster's entrance nodes; those costs become the edges of a small "abstract graph". At query time it inserts the source and goal into the abstract graph, runs A* there, then refines each abstract edge into a real path. The Botea paper reports up to 10× faster searches than a highly optimized A*, with paths within 1% of optimal after smoothing. Later hierarchical schemes, such as Sturtevant and Buro's partial-refinement A* (PRA*), tune the same trade.
Navigation in shipped 3D games

Many 3D games don't search a grid at all. They search a navmesh, often one built by Recast[2], which merges walkable space into convex polygons at build time (a geometric partition, where HPA*'s is a grid of clusters), and query it at runtime with Detour, which runs A* on the polygon graph with a straight-line heuristic[31]. The navmesh does the job HPA*'s abstraction does, shrinking the search graph: A* runs over thousands of polygons instead of millions of grid cells. Recast's README lists Unity, Unreal, Godot, and O3DE among the engines it powers; engines with in-house navmeshes, such as CryEngine[29], run the same kind of A* over their own polygon or triangle meshes.
